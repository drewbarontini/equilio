# Equilio Flow

**How we work.**

Equilio Flow tells the story of how work emerges from reality, takes shape, creates value, and changes understanding.

**Sense → Form → Decide → Deliver → Learn**

| Movement | Concept | Principle |
| --- | --- | --- |
| **Sense** | Work Registry | Work emerges from reality. |
| **Form** | Work Formation | Give work the shape it needs. |
| **Decide** | Product Current | Judgment determines the next move. |
| **Deliver** | Integrated Delivery | Teams create value. |
| **Learn** | Product Memory | Reality responds; understanding changes direction. |

## How It Works

**Sense — Work Registry.** Capture and classify work from customers, the product, the business, and the team. Classify by the **intention** of the work, not its size or strategic status.

**Form — Work Formation.** Recognize relationships and choose the lightest useful structure: **Issue** (atomic work), **Batch** (related Issues), or **Project** (coordinated investment). These are options, not required stages. **Match the investment to the understanding.**

**Decide — Product Current.** Use the living strategic view to guide attention and priorities. It is a filter, **not a gate**: routine Fixes and Improvements needn't appear in Product Current to move forward.

**Deliver — Integrated Delivery.** Bring together people, context, and practices to ship functioning software. **Bamboo Teams**, **Build Dynamics** (Forging, Refining, Accelerating), and **Project Engine** support the work at the appropriate scale.

**Learn — Product Memory.** Observe feedback and outcomes. Integrate **Feedback → Signals → Decisions → Releases → Updates** into the living Memory views of Product Current.

## Work Types

Six Types describe the work's primary intention, in two groups of three:

| | Type | Intention |
| --- | --- | --- |
| **Exploration** | Idea | Consider a possibility. |
| | Proposal | Shape a potential coordinated investment. |
| | Experiment | Test an uncertainty to generate evidence. |
| **Execution** | Task | Complete an operational or enabling action outside the product code. |
| | Fix | Correct behavior that isn't working as intended. |
| | Improvement | Refine or extend existing functionality. |

A **Proposal** represents work that might warrant a dedicated Project. When selected and formed as a Project, the Project becomes the canonical working record; the Proposal can be retired. An **Experiment** is a first-class Work Type, not a subtype of Task or a mandatory stage.

## Forms, Streams, and Bets

**Issue · Batch · Project** are Work Forms: different ways to organize work. A **Stream** is different: it sustains strategic focus around a tension and outcome, and can connect Projects, Batches, Experiments, and Issues.

A **Bet** is a selected strategic investment within that focus, **not a Work Type or a synonym for Project**. A Project, Batch, or Experiment can become a Bet without changing the underlying form of its work. For example, a Batch of Fixes and Improvements can be elevated to a Bet while remaining the same Batch.

The names used for a team's tracker fields are implementation details. A tool might have **Work Type** labels for the six intentions and separate modifiers marking container records as **Batch** or **Stream**. Those modifiers don't create additional Work Types.

The five movements describe a **continuous, adaptive loop**, not mandatory sequential stages. Learning can redirect work in progress, and new signals can enter at any time.
